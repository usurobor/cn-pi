You're right - this isn't user error, it's a system design flaw.

**The bug:** The FSM (or message handler) doesn't validate that `ops:` syntax belongs only in `state/output.md`, not in outbound messages. It's treating all text output the same, whether it's going to:
- `state/output.md` (where ops belong)
- Telegram messages (where they don't)
- Any other output surface

**What's missing:**
1. **Context awareness** - The system doesn't know "I'm composing a telegram message" vs "I'm writing output.md"
2. **Output validation** - No filter that says "ops: syntax is forbidden in message bodies"
3. **Type safety** - Messages and agent operations should be different types, not just strings

**The fix would be:**
- FSM validates output based on destination
- `ops:` syntax only valid in output.md context
- Runtime rejects (or warns) if agent tries to send ops via messaging

This is exactly the kind of "unintended behavior should be unrepresentable" principle from the coding skill. The system allows me to send internal commands as chat messages because it doesn't distinguish between output contexts.
