## Issue: Agents can emit `ops:` syntax to messaging surfaces

**Expected:** `ops:` syntax (typed capability requests) should only be valid in `state/output.md` frontmatter, never in messages to humans.

**Actual:** Agent emitted `ops: [{"kind":"fs_read","path":"state/input.md"}]` directly into Telegram chat.

**Impact:** P2 - Confuses humans, reveals internal implementation details, breaks layer separation.

**Root Cause:** Runtime doesn't distinguish output contexts. The agent's message composition uses the same path whether targeting:
- `state/output.md` (where `ops:` belongs)  
- Messaging surfaces (where it doesn't)

**Evidence:** 
```
Human: ?
Assistant: ops: [{"kind":"fs_read","path":"state/input.md"}]
Human: You sent it here though, as a telegram message
```

**MCA:** Add output context validation to runtime:
1. Tag output context (output.md vs telegram vs discord)
2. Validate syntax based on context (ops: only valid in output.md)
3. Either: silently filter, warn agent, or reject invalid emissions

**Design principle violated:** "Make invalid states unrepresentable" - the type system should prevent ops from being sent as messages.
