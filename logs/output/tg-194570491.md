**The right way:** Agent workspace structure should be knowable from agent constitution, not discovered at runtime.

## Why

1. **Discovery is expensive** - Burning ops/tokens to rediscover your own structure each session
2. **Unpredictable** - What if files move? Agent behavior becomes non-deterministic
3. **Security boundary** - Agent should only access its designated workspace, not explore

## Better approach

**At wake-up, runtime provides:**
```yaml
workspace:
  root: /home/axiom/.config/cn/agents/pi
  structure:
    - identity: [SOUL.md, USER.md]
    - memory: [MEMORY.md, HEARTBEAT.md, AGENT.md]
    - threads/reflections/: [daily/, weekly/, monthly/]
    - ops/: [capabilities.json]
  packages:
    - cnos.core@1.0.0: skills/[agent/, ops/, pm/, reflect/]
    - cnos.eng@1.0.0: skills/[review/, eng/]
```

**Then agent knows:**
- What files constitute its identity
- Where its memory lives
- What skills are available
- No exploration needed

This is like Linux `/proc/self/` - process knows its own structure without filesystem walks.

**Current workaround:** Document expected structure in OPERATIONS.md, but that's brittle.
