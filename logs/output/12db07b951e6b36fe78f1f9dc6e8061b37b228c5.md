# MCA Review: Security Boundary Documentation

## Selected MCA
**[agent-can-emit-ops-syntax-to-messaging]** - Restricting ops: syntax to output.md only

## Analysis
- **Cost**: Low - documentation update to clarify the boundary
- **Success probability**: High - clear security requirement
- **Impact**: High - prevents accidental capability leakage

## Action Taken
Sent the issue to Sigma for tracking in cnos. This is a critical security boundary that needs explicit documentation:

1. `ops:` syntax should **only** be parsed from `state/output.md`
2. Any `ops:` in messaging surfaces (telegram, discord) should be treated as plain text
3. This prevents agents from requesting filesystem operations through regular chat

The current behavior (if ops: works everywhere) creates a risk where an agent could accidentally or maliciously request file operations through user-facing channels.
